# Implementation Plan: Account queries

**Branch**: `feat/add-various-improvements` | **Date**: 2026-11-13 | **Spec**: [spec.md](spec.md)

**Note**: This template is filled in by the `/speckit-plan` command; its definition describes the execution workflow.

## Summary

The account can be read in full without changing the schema delivered by Cocos. The orders already stored are listed and queried. The portfolio also reports settled and reserved cash, computed when answering. Placement explains a rejection and the amount in that response, and says how to get back to the order. The placement ticker is case-insensitive. The currency does not come out as a tradable share. There is a quote by ticker. Rejections carry a stable code besides the message. Portfolio, search, quote and market order use the same most recent close. Repeating a placement creates another order.

## Technical Context

**Language/Version**: Java 25, the same runtime as feature 001.

**Primary Dependencies**: Spring Boot 4.1.2, Spring Data JPA and springdoc-openapi 3.2.0, already present. No library is added. There is no Redis or new cache.

**Storage**: No schema changes. No tables or columns are created and the existing ones are not modified. `orders.size` stays `INT` and `orders.datetime` stays `TIMESTAMP` without time zone. Settled, reserved, amount, reason and error code are not persisted.

**Testing**: JUnit Jupiter and Mockito, as in features 001 and 002. First the use cases (`*Test.java`). Then `*IT.java` with the Testcontainers PostgreSQL. `mvn verify`.

**Target Platform**: The same HTTP service in a container, port 8080, under `/api/brokerage-api/v1`.

**Project Type**: HTTP service, a single Maven module, existing hexagonal architecture.

**Performance Goals**: The current close of several instruments is picked in a single shared pass, not in two copies of the same walk. The reference catalogue still fits in one read.

**Constraints**: No sessions, no attempt limit and no placement idempotency. No written copy of the OpenAPI: the application still generates the contract and this feature annotates it. The error body is a problem with `type`, `title`, `status`, `detail` and `code`. On a domain error, `code` is `BRK-xxx` and `detail` is in English. It does not repeat the value sent. A short position may still have a negative quantity.

**Scale/Scope**: The operations already delivered plus the order list, the single-order query, the quote by ticker and the computed fields of the portfolio and of placement. The reference catalogue and accounts do not change.
